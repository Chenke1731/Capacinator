## 1. 背景与问题定性

### 1.1 信任崩塌的事件链（2026-09-24 ~ 09-25）

| # | 事件 | 性质 |
|---|------|------|
| 1 | 主套件静默收集 0 个测试仍"全绿" | 基建说谎 |
| 2 | 全量基线 522/807 失败，~140 个是 `__dirname`/helper 改名/占位 FK 类低级错误 | 低级问题直抵最贵层 |
| 3 | 约 60 个"测试"实为纯 API 断言，占着浏览器层 14 分钟预算 | 分层缺失 |
| 4 | 现代化过程中大量 `if(isVisible)` 守卫与放松断言，部分用例检测方向反转 | 资产不可信 |
| 5 | 检测力从未被度量：7 个真 bug 全靠人工调查挖出，非套件拦截 | 无有效性证据 |

### 1.2 根因

1. **契约层缺位**——API 契约类断言全部堆在 e2e。
2. **spec 文件不在任何 typecheck 范围内**——未定义名/改名漂移活着进库。
3. **测试无准入审查**——用例不必回答"拦什么"，守卫型弱断言畅通无阻。
4. **基建无自证机制**——收集数、fixture 有效性、种子一致性均无守卫。
5. **检测力被"绿灯"冒充**——绿 = 与今日行为一致，≠ 行为变坏时会红。

---

## 2. 设计公理

1. **可证伪性**：每条用例必须存在明确的"产品怎么坏它就红"的路径，写作时标注对应的击杀变异。说不出这条路径的用例是占位符，不入库。
2. **检测力是度量属性**：有效性只能被变异校准证明，不能被"它是绿的"证明。
3. **基建即被测对象**：执行框架必须有自动化的"证明自己能失败"的机制。
4. **一事一源**：每个关注点只在最低够用层断言一次。
5. **成本分层准入**：贵的层只接收被便宜层过滤后仍需它的问题。
6. **宁缺毋滥**（v1.1 新增）：不引入养不起的常设机制；机制只在有对应事故/痛点时存在。

## 3. 总体架构：六层反馈塔

```
成本      层                 职责                              触发        预算
───────────────────────────────────────────────────────────────────────────
0-40s     L0 静态门          语法/类型/未定义名/导入完整性       每次保存    45s
          lint + tsc(含spec)
10s       L1 单元            纯逻辑(mock 边界)                  每次保存    15s
          Jest 4209 测
跟随栈    L2 集成契约        API 真服务器：信封/必填/FK/规则     提交前*     —
          Playwright api 项目
≤2min     L3 红线旅程        用户旅程，全强断言零守卫            提交/合并门  2min
          ~18 测
≤12min    L4 底线全量        广 UI 覆盖（待证明资产）            推送/每夜   12min
按需      L5 深度            多用户/负载/性能                   里程碑      不限
```

*L2 随 e2e 栈启动运行；"提交前 60 秒无服务器"版本（Jest+临时库）仅当启动等待成为真实痛点时再建（v1.1 修订）。

## 4. 各层详细设计

### L0 静态门

- **工具**：ESLint（现状）+ `tsc --noEmit` 三份配置（client / server / **新增 tsconfig.spec.json 覆盖 tests/e2e**）。
- **为何新建 spec 配置而非复用 tsconfig.test.json**：后者 `types: ["node","jest","@testing-library/jest-dom"]` 与 @playwright/test 的 expect 全局类型冲突，且该配置目前无任何钩子/CI 执行（死配置）。tsconfig.spec.json 反向只挂 @playwright/test 类型。
- **必含规则**：typecheck 预算零容忍类（TS2304/TS2552 cannot-find-name 一票否决，机制已存在于 `scripts/client-typecheck-budget.mjs`；**v1.2：pre-commit 尚未接线 client/spec 两份配置——接线是 P1 的显式动作，不是"已上线"**）。
- **拦截面（实证）**：522 个 e2e 失败中 ~140 个在 L0 即死。
- **入位守卫（v1.2）**：`lint:ui`、`verify:site`、`verify:visual`（pixelmatch 基线比对）按成本挂入本层——spec 涉及 UI 时 `lint:ui` 进 pre-commit；`verify:*` 进 CI（L0 步骤），视觉基线变更需随 PR 说明。
- **入口**：pre-commit（与 migration 守卫同钩子）+ CI。

### L1 单元（现有，保留）

- **边界**：纯函数与 mock 边界内的逻辑——校验器、计算器、控制器(mockDb)、工具函数。
- **现状**：163 套件 / 4,209 测 / 10.5s，全绿。
- **诚实定位（v1.1）**：与 e2e 同源，检测力同样未经变异验证；因保留成本近零（10s）不做专项审计，**机会性抽审**（触碰时顺带核对其断言强度）。本会话一次实证拦截：branchFromParent 改动被其 mock 队列测试抓住。
- **纪律**：每条业务规则（分配上限、日期先后、信封生成）必须在此层有对应用例。

### L2 集成契约层（v1.1 修订宿主）

- **宿主**：**Playwright api 项目**（现有 `api` project，request-context 无浏览器）——零新基建，且对真实服务器（含中间件、真实迁移+种子）断言，契约保真度高于 mock 边界。
- **断言范围**：信封形状（`{success,data}`/分页/错误体）；必填与校验（`assignment_date_mode` 必填、分配 0-200、日期先后）；契约闭环（create 返回 id 可直接 update/delete——本会话修的 404 类）；FK/级联（场景带子拒删、baseline 不可删）；事务回滚无残渣。
- **迁移来源**：`suites/api/*`(35)、`assignment-contracts`(8)、报表 accuracy 的 API 侧断言、`transaction-safety` API 侧——约 40-60 条精选，不追 150。
- **Jest 化触发条件**（记录，不实施）："每次提交等 e2e 栈启动（60-90s）"成为日常抱怨两次以上。

### L3 红线旅程（重写，不抢救旧资产）

- **构成（18 条，每条标注拦截的变异）**：

| # | 旅程 | 挂了意味着 |
|---|------|-----------|
| 1 | 框架自证：登录注入有效 + 每主页面锚点存在 + **axe 无障碍冒烟**（@axe-core/playwright 已装未用） | 基建坏，其余结果不可信 |
| 2 | 应用启动、侧边栏导航五页可达 | 应用不可用 |
| 3-5 | 人员/项目/分配 各一条完整 CRUD（UI 驱动） | 核心实体不可管理 |
| 6 | 场景切换改变数据世界（对照断言） | what-if 分析失效 |
| 7 | 报表三页渲染真实数据（字段级断言） | 决策依据失效 |
| 8 | Excel 导入冒烟（模板文件 → 行数变化） | 核心入口功能失效 |
| 9 | 导出冒烟（点击 → download 事件 + 文件名） | 数据出不去 |
| 10-18 | 冲突检测、基线保护、审计留痕等各一条强断言 | 数据安全语义失效 |

- **铁律**：零 `if(isVisible)` 守卫、零 `catch(()=>null)` 放松、每条含至少一个数据级断言。
- **预算**：≤2 分钟（登录复用 + 页面预热已就绪）。

### L4 底线全量（v1.1 重定位：待证明资产；v1.2 过渡态声明）

- **立场**：红线 18 条 + 契约层之外，**每个 L4 用例的边际价值未证明**。默认从现代化后的 UI 交互测试（过滤/排序/内联编辑/弹窗，~250 测）中**只保留通过触碰时分级的 A 类**；B 类（计数/纯可见性）需击杀数据佐证才留；C 类删除。
- **不做运动式全量审计**（v1.1 砍除）：A/B/C 在文件被触碰时打，未触碰的保持现状待跑。
- **过渡态（v1.2 声明、v1.3 修正基线、v1.4 修正重叠账目）**：L4 全量 = **530 测**（chromium 316 + scenario 214，含 141 个从未摸底者），已知部分 316 测/14min，未知部分时长待基线——**收割（P4 下沉 + 归并 + 触碰分级 + 141 摸底）完成前 L4 常态超预算黄**。棘轮锚点 = 收割完成时（判据见 §9 P4）。不采用 tag 白名单方案（未标注即不跑 = 收集塌方同族的静默覆盖丢失；全量打 tag = 运动式普查换皮）。
- **执行**：推送/每夜，后台不阻塞。

### L5 深度

- git-sync 多用户、负载/性能预算、大规模数据。触发：里程碑或手动。

## 5. 可信度子系统（v1.1 收敛为轻机械）

### 5.1 收集数守卫（v1.4 升级：按配置精确锚定）

CI/本地跑 e2e 前：对**每份配置**做 `playwright --list` 计数与 `tests/e2e/.collection-floor.json` 比对——格式 `{ "main": N, "scenario": M }`，**任何方向的漂移都红**（不只下限：数量变多同样是账实漂移，可能混入僵尸/误收集，v1.4 的 3 个归档僵尸即活例——最小下限守卫锚在含僵尸的 76 上反而给它背书）。
配套元断言：**所有配置对 `archived/` 的收集数为零**。**"0 测试全绿"与"归档僵尸静默跑绿"两类事故永久不可复现。** 全设计性价比最高的一件。

### 5.2 元测试（5-8 条，进 CI）

验证：登录状态文件 schema、种子关键锚点（类别前缀、物化分配行）、fixture 依赖的 helper 方法存在、四端口无交集断言。

### 5.3 变异校准（一次性，非常设）

- 红线重写完成后，**人工注入 20 个代表性变异跑一轮**（四类故障模型：UI 锚点漂移 / API 契约变更 / 业务规则反转 / 数据丢失路径），产出红线击杀率报告与逃逸清单。
- 红线要求 P0 类（用户不可用级）**100% 击杀**，逃逸即补用例。
- **不建常设 harness/阈值/再入规则**（v1.1 砍除）：后续防线是写作纪律——每条新用例标注击杀变异（准入三问之一）。
- **标注完整性检查（v1.2）**：~20 行结构脚本进 P1——L3 每个 `test()` 必须伴随击杀变异标注注释，缺标注即 P2 验收不通过。P3 校准验的是标注的真实性（变异真被杀），此检查验的是完整性（每条都有）——两者合起来验收口径才闭合。
- 重跑时机：红线结构大改时人工再来一轮，不日历驱动。

### 5.4 预算零容忍类（已上线）

cannot-find-name 类 TS 错误一票否决；扩展覆盖 spec 配置。

## 7. 用例治理

### 断言分级（触碰时打，不搞普查）

| 级 | 定义 | 准入 |
|----|------|------|
| A | 断言只有功能正常才成立的数据/跳转/字段值 | L3 全部；L4 触碰时升级至此 |
| B | 计数、纯可见性等弱信号 | 仅 L4，留任需击杀佐证 |
| C | 守卫跳过即过、catch 后不判 | **禁止**，发现即删或重写 |

### 准入三问（新用例评审）

1. 拦什么回归？（一句话）
2. 哪个变异能杀死它？（描述即可，校准时对账）
3. 属于哪层？为什么不能下沉一层？

### 退役

功能移除 → 用例归档 + 覆盖缺口登记 → 触碰即重建。

## 9. 实施路线图（v1.2，~2.75 天）

| 阶段 | 内容 | 验收 | 量级 |
|------|------|------|------|
| **P0** | **最小 CI workflow**（`.github/workflows/test.yml`：node setup → lint → tsc 三配置 → Jest[**只跑 client + server-unit**——server-integration 依赖共享库，CI 干净检出无库必挂，库供给记开放问题] → **e2e job 骨架：收集下限守卫 + smoke**） | push 即跑，全部 job 结果可见 | **0.25d** |
| P1 | spec 纳入 typecheck + **pre-commit 接线（client tsc + 预算 + spec tsc，现状只跑 root tsc）** + 收集下限守卫 + 元测试 5-8 条 + **L3 标注完整性检查脚本** | CI 与钩子两者都真实生效（非"脚本存在"） | 0.5d |
| P2 | L3 红线重写 18 条 | ≤2min；零守卫零放松；**每条标注击杀变异（由检查脚本验收）** | 1d |
| P3 | 变异校准一轮（20 个变异） | 红线 P0 击杀 100%；逃逸清单闭环 | 0.5d |
| P4 | API 断言迁入 api 项目 + **scenario 归并**（专用配置 testMatch 扩至 `.*scenario.*` + 加 archived 排除 + 主配置删 scenarios 项目 + 删 firefox/mobile 空壳）+ **141 摸底** | 迁移完成；**收割判据：L4 台账闭合（530 测全部分级一次）或实测 ≤12min，先到者 = 棘轮锚点（收集守卫须同时成立，防清仓套利）** | 0.5d |

**P0 是唯一硬前提**（v1.2 新增）：没有执行器，P1 的验收从定义上不可验收。
