# Capacinator 测试框架设计方案

版本：v1.0（2026-09-25）
状态：设计定稿，待实施
裁决记录：L2 宿主 = Jest + 真实 SQLite；变异基准 = 套件结构变更触发 + 红线变更即时重跑；红线范围 = 15-20 条旅程含导入/导出各一条冒烟。

---

## 1. 背景与问题定性

### 1.1 信任崩塌的事件链（2026-09-24 ~ 09-25）

| # | 事件 | 性质 |
|---|------|------|
| 1 | 主套件静默收集 0 个测试仍"全绿"（发现于 09-25 晨） | 基建说谎 |
| 2 | 全量基线 522/807 失败，其中 ~140 个是 `__dirname`/helper 改名/占位 FK 类低级错误 | 低级问题直抵最贵层 |
| 3 | 约 60 个"测试"实为纯 API 断言，占着浏览器层 14 分钟预算 | 分层缺失 |
| 4 | 现代化过程中大量 `if(isVisible)` 守卫与放松断言，部分用例检测方向反转 | 资产不可信 |
| 5 | 检测力从未被度量：7 个真 bug 全靠人工调查挖出，非套件拦截 | 无有效性证据 |

### 1.2 根因

1. **L2 集成契约层不存在**——API 契约类断言全部堆在 e2e。
2. **spec 文件不在任何 typecheck 范围内**——未定义名/改名漂移活着进库。
3. **测试无准入审查**——用例不必回答"拦什么"，守卫型弱断言畅通无阻。
4. **基建无自证机制**——收集数、fixture 有效性、种子一致性均无守卫。
5. **检测力被"绿灯"冒充**——绿 = 与今日行为一致，≠ 行为变坏时会红。

---

## 2. 设计公理

1. **可证伪性**：每条用例必须存在明确的"产品怎么坏它就红"的路径，且能用一个变异（mutation）表达。说不出这条路径的用例是占位符，不入库。
2. **检测力是度量属性**：有效性只能被变异基准证明，不能被"它是绿的"证明。
3. **基建即被测对象**：执行框架必须有自动化的"证明自己能失败"的机制。
4. **一事一源**：每个关注点只在最低够用层断言一次。
5. **成本分层准入**：贵的层只接收被便宜层过滤后仍需它的问题。

---

## 3. 总体架构：六层反馈塔

```
成本     层                职责                              触发        预算
──────────────────────────────────────────────────────────────────────────
0-40s    L0 静态门         语法/类型/未定义名/导入完整性       每次保存    40s
         lint + tsc(含spec)
10s      L1 单元           纯逻辑(mock 边界)                  每次保存    10s
         Jest 4209 测
≤60s     L2 集成契约       API 真库：信封/必填/FK/规则         提交前      60s
         Jest + 临时 SQLite
≤2min    L3 红线旅程       用户旅程，全强断言零守卫            提交/合并门  2min
         Playwright ~18 测
≤12min   L4 底线全量       广 UI 覆盖                         推送/每夜   12min
         Playwright ~250 测
按需     L5 深度           多用户/负载/性能                   里程碑      不限
```

层间准入：Lₙ 只跑 Lₙ₋₁ 全绿后的内容。任何层发现下层应拦截的问题 = 下层缺口，记缺口表。

## 4. 各层详细设计

### L0 静态门

- **工具**：ESLint（现状）+ `tsc --noEmit` × 三份配置（client / server / **新增 tsconfig.spec.json 覆盖 tests/e2e 与 shared 测试代码**）。
- **必含规则**：typecheck 预算零容忍类（TS2304/TS2552 cannot-find-name 一票否决，已上线于 `scripts/client-typecheck-budget.mjs`，扩展至 spec 配置）。
- **拦截面（实证）**：本方案实施前 522 个 e2e 失败中 ~140 个（`__dirname`、`waitForPageReady` 不存在、helper 三代改名）在 L0 即死。
- **入口**：pre-commit（与现有 migration 守卫同钩子）。

### L1 单元（现有，保留）

- **边界**：纯函数与 mock 边界内的逻辑——校验器、计算器、控制器(mockDb)、工具函数。
- **现状**：163 套件 / 4,209 测 / 10.5s，全绿。
- **新增纪律**：每条业务规则（分配上限、日期先后、信封生成）必须在此层有对应用例；产品 PR 无对应单测的规则类改动不合并。

### L2 集成契约层（**新建，本设计最大增量**）

- **宿主**：Jest 新项目（jest.config.cjs 增 `integration-contract` project），`better-sqlite3` 指向**每 worker 独立的临时库文件**；globalSetup 跑 migrations + 复用 `e2e-test-data-consolidated` 种子（种子即唯一夹具源）。
- **断言范围**：
  - 信封形状：`{success, data}`、分页、错误体；
  - 必填/校验：`assignment_date_mode` 必填、分配 0-200、日期先后；
  - 契约闭环：create 返回的 id 可直接 update/delete（本会话修的 404 类）；
  - FK/级联：场景删除带子拒绝、baseline 不可删；
  - 事务：回滚后无残渣。
- **迁移来源**（从 L4 下沉，约 60-80 测）：`suites/api/*`(35)、`assignment-contracts`(8)、报表 accuracy 系列的 API 侧断言、`transaction-safety` API 侧。
- **预算**：~150 测 ≤60s。
- **本层价值（实证）**：本会话修出的信封/必填/契约类失败在此层 10 秒级复现，不再占用 14 分钟浏览器预算。

### L3 红线旅程（重写，不抢救旧资产）

- **构成（18 条，每条标注拦截的变异 ID）**：

| # | 旅程 | 挂了意味着 |
|---|------|-----------|
| 1 | 框架自证：登录注入有效 + 每主页面锚点存在 | 基建坏，其余结果不可信 |
| 2 | 应用启动、侧边栏导航五页可达 | 应用不可用 |
| 3-5 | 人员/项目/分配 各一条完整 CRUD（UI 驱动） | 核心实体不可管理 |
| 6 | 场景切换改变数据世界（对照断言） | what-if 分析失效 |
| 7 | 报表三页渲染真实数据（字段级断言） | 决策依据失效 |
| 8 | Excel 导入冒烟（模板文件 → 行数变化） | 核心入口功能失效 |
| 9 | 导出冒烟（点击 → download 事件 + 文件名） | 数据出不去 |
| 10-18 | 冲突检测、基线保护、审计留痕等各一条强断言 | 数据安全语义失效 |

- **铁律**：零 `if(isVisible)` 守卫、零 `catch(()=>null)` 放松、每条含至少一个数据级断言（不是纯可见性）。
- **预算**：≤2 分钟（登录复用 + 预热已就绪）。

### L4 底线全量（现有套件清理后保留）

- **构成**：现代化后的 UI 交互测试（过滤/排序/内联编辑/弹窗），扣除下沉 L2 的部分，约 250 测。
- **准入**：通过断言分级审计（见 §7），C 级清除后方可入此层。
- **执行**：推送/每夜，后台不阻塞。

### L5 深度

- git-sync 多用户、负载/性能预算、大规模数据。触发：里程碑或手动。

## 5. 可信度子系统（四机制）

### 5.1 收集数下限守卫

CI/本地跑 e2e 前：`playwright --list` 计数与 `tests/e2e/.collection-floor.json` 阈值比对，低于即红。**"0 测试全绿"永久不可复现。**

### 5.2 元测试（进 CI 的基建自检）

Jest 元套件验证：登录状态文件 schema、种子关键锚点（类别前缀、物化分配表行存在）、fixture 依赖的 helper 方法存在、四端口无交集断言。**基建证明自己活着。**

### 5.3 变异基准（检测力的唯一货币）

- **故障模型四类**：

| 类 | 注入方式示例 | 对应层 |
|----|-------------|--------|
| UI 锚点漂移 | 改一个 data-testid/aria-label、删一个按钮 | L3/L4 |
| API 契约变更 | 信封去 data、字段改名、必填移除 | L2 |
| 业务规则反转 | 上限判断取反、日期校验删除断言 | L1/L2 |
| 数据丢失路径 | 级联删除漏子行、事务不回滚 | L2 |

- **实现**：`scripts/mutation/` 下 mutants 清单（id、类、目标文件、变换、预期击杀层）+ runner（逐个 patch → 跑目标层 → 还原 → 记录击杀/逃逸）+ 报告。
- **阈值**：L3 对 P0 类（用户不可用级）**100% 击杀**；L4 ≥85%。
- **再入**：套件结构变更 / 红线用例变更时重跑对应类；不日历驱动。

### 5.4 预算零容忍类（已部分上线）

cannot-find-name 类 TS 错误一票否决；扩展覆盖 spec 配置。

## 6. 数据与环境策略

| 世界 | 端口 | 数据 | 生命周期 |
|------|------|------|---------|
| dev | 3110/3120 | 开发者库 | 常驻 |
| e2e | 3111/3122 | 每 run 重建种子库 | 测试所有 |
| L1 | — | mock | 进程 |
| L2 | — | 每 worker 临时 SQLite（migrations+种子） | 进程 |

**种子三原则**（三次脱节教训）：
1. 种子是唯一夹具源；与产品语义耦合处（类别前缀 ↔ projectCategories、物化分配表 ↔ Smart 门槛）双向注释链接。
2. 测试禁造 baseline 场景（不可删 + 抢自动选择——已两次污染事故）。
3. 引用 id 一律运行时解析（/api/roles、/api/project-sub-types 首行），禁止占位字符串。

## 7. 用例治理

### 断言分级

| 级 | 定义 | 准入 |
|----|------|------|
| A | 断言只有功能正常才成立的数据/跳转/字段值 | L3/L4 全部 |
| B | 计数、纯可见性等弱信号 | 仅 L4，需变异佐证 |
| C | 守卫跳过即过、catch 后不判 | **禁止**，发现即删或重写 |

### 准入三问（新用例 PR 模板）

1. 拦什么回归？（一句话）
2. 哪个变异能杀死它？（mutants 清单 ID）
3. 属于哪层？为什么不能下沉一层？

### 退役

功能移除 → 用例归档 + 覆盖缺口登记于债务文档缺口表 → 按触碰即重建原则恢复。

## 11. 风险与开放问题

1. L2 临时库的 migrations 全量执行耗时需实测（46+ migrations）；超 10s 则快照预热。
2. 变异 runner 的 patch 还原需防污染（git checkout HEAD -- 而非暂存区——本会话事故教训已入记忆）。
3. Excel 导入红线依赖稳定模板文件；模板演进需同步该用例（属正常维护）。
4. workers 4→6 提速需 SQLite busy_timeout 先行，暂缓（收益 3-4 分钟 vs 断连风险）。
