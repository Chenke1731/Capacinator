# UI 生成契约（Generation Contract）v2

> **推导顺序**：先从"这个项目本身是什么、支撑什么决策"演绎出设计支柱（覆盖全部应有的维度），
> 历史失败只作为各支柱下的佐证与校准（它们是维度被违反过的实例，不是维度的来源）。
> 失败归纳清单的致命伤：覆盖面恰好等于已发生过的意外，而失败空间远大于踩过的坑。
>
> 维护规则：①支柱结构只随项目本质演进（如新增协作场景才动支柱）；②每次"用户看见而我没看见"
> 的失败，归位到某根支柱下作佐证，并检查该支柱的推导是否有缺口要补。

## 项目本质与推导

**本质**：交付领域人力主管用一个工具代替 Excel 管理交付线的人员排布。工具的全部价值
= 通过它做出的排产决策【正确、快、有把握】。

| 价值要求 | 推导出的支柱 |
|---|---|
| 决策正确 → 计划状态必须是真的 | **A 计算可信** + **B 语义透明** |
| 决策快 → 排产是"看→调→看后果→再调"的循环 | **C 决策流就绪** |
| 有把握 → 真实环境下不撒谎、操作不出事 | **D 呈现健壮** + **E 操作安全** |

## 三层防线模型

| 层 | 时机 | 干什么 | 性质 | 业界方法来源 |
|---|---|---|---|---|
| ① 生成契约 | 写代码前/中 | FMEA-lite 支柱失效排查 + pre-mortem 推演 | 前置（演绎） | FMEA；Pre-mortem (Klein) |
| ② 认知走查 | 交付前，跑守卫前 | **全称状态检查器**（verify:states，双主题全交互元素×状态×对比度/命中/遮挡/越界/字号/贴锚）+ 认知走查四问，人眼只管观感 | 前置（补演绎盲区） | Cognitive Walkthrough + 计算化启发式评估 |
| ③ 守卫 | 交付时 | verify-boards / verify:visual / lint:ui / 单测 | 兜底 | 启发式评估的机器化 |

## 生成前协议（第①层的工作步骤）

**1. FMEA-lite 支柱失效排查**（失效模式与影响分析，汽车/航天可靠性工程）：
从功能出发问"会怎么失效"，不从事故出发。对本次触及的每根支柱，列 1-3 个潜在失效
模式与设计对策，5-10 分钟。模板：

| 触及支柱 | 潜在失效模式 | 设计对策 |
|---|---|---|
| 例:D3 呈现健壮 | 全局 button padding 吃光定宽按钮内容盒 | 同块显式 padding; lint:ui |
| 例:A2 新鲜度 | 编辑池后详情页/看板仍显示旧值 | invalidate 覆盖全部消费方清单 |

**2. Pre-mortem 推演**（事前验尸法，Gary Klein）：写代码前一句话回答——
"假设两周后用户为这个功能发了红框截图，最可能在圈什么？"把最可能的三个答案变成
设计约束。这是对演绎盲区最便宜的探针。

**3. 红线速查**：
- 自定义控件先查 client/src/index.css 与 client/src/styles/design-system.css 的
  元素级规则（button 默认 padding/背景/44px 命中）并显式重置；定宽按钮同块必写
  padding（`npm run lint:ui` 静态拦截）。
- **新浮层/选择器控件优先用已装的 Radix 原语**（dropdown-menu/select/dialog/tabs/
  toast）——视口碰撞翻转、Esc/外点关闭、焦点管理、a11y 免费。手写浮层仅限
  useCellPopover 体系内的同族扩展（其已知缺口：贴近视口底部不自动翻转，靠 clamp 保底）。

## 五支柱维度表

每条 = 支柱要求 + 生成时怎么查。〔斜体〕为该维度被违反过的历史佐证。

### A 计算可信 —— 数字就是产品本身，错的数字比没有工具更糟

- **A1 聚合正确**：池+实名、暂停排除、跨侧汇总算对；聚合逻辑改动必须带服务端测试。
- **A2 新鲜度**：任何编辑后，所有受影响的数字立即反映——invalidate 覆盖全部消费方
  （列表/详情/看板/告警）；写方防共享键投毒（`Array.isArray(payload) ? payload : payload?.data || []`）。
- **A3 单位一致**：FTE / % / 人月 / 人数全站同单位同符号，展示处标单位。
- **A4 边界数值**：0、空、负载>100%、池全未实名、负值——退化状态数字不崩、界面不骗
  （空白与 0 要可区分；超载要有视觉语言）。
- **A5 规模退化**：数据量 ×10（项目/人员/分配）时计算与渲染不塌；批量接口不分页拉全量的要有上限意识。

### B 语义透明 —— 不看文档能读懂计划状态

- **B1 域语言统一**：实名/池、设/开、RP 节奏、P 档——同一概念在列、气泡、详情、语言包
  同一套词与视觉编码。〔"列与气泡术语不同构"教训〕
- **B2 自标注**：每个数字带单位/标签；每个编辑控件声明"改什么、步长、后果"；
  "此处改什么、别的去哪改"一句话说清。〔"完全没办法知道编辑逻辑"事故〕
- **B3 状态可预测**：推进状态/执行编辑前，用户能推断哪些数字会变、方向如何
  （至少在 tooltip/气泡里说明影响面）。
- **B4 告警可读**：黄牌告警的触发规则能从界面理解（为什么亮、怎么消）。

### C 决策流就绪 —— 界面就是"看→调→看后果→再调"循环本身

- **C1 就地性**：高频操作落在列表页本体，零弹窗；"要先点进详情才能做"的高频操作是交互债。
  〔弹窗流教训〕
- **C2 回路速度**：从一个排产问题到答案的点击数最少（搜人→看负载→分配一屏内完成）；
  首屏密度服务决策不服务美观。〔工具栏吃掉 520px 首屏教训〕
- **C3 后果可见**：每次调整后，受影响的量（对侧负载、告警、分组位置）就地反馈——
  行 flash/组头高亮只是起点，终极是调整点旁边能看到关键后果。
- **C4 视图组织服务排博弈**：分组（版本）、排序（P 档）、筛选的逻辑要能讲出决策含义。

### D 呈现健壮 —— 工件必须在自己所处的渲染环境里真实存在

- **D1 双主题物理渲染**：浅色+深色各渲染一次并亲自看；用户用浅色。〔两轮白干教训〕
- **D2 视口矩阵**：1600 与 1366 各过；断点行为（如 <1440 隐藏列）是有意的。
- **D3 全局规则兼容**：自定义控件前先查 index.css / design-system.css 元素级规则
  （button 默认 padding/背景/44px 命中）并显式重置；**定宽按钮同块必写 padding**
  （`npm run lint:ui` 静态拦截）。〔加减号零宽物理消失事故〕
- **D4 物理可见**：图标 rect 宽高>0、文字与底色可辨；按钮盒达标 ≠ 内容可见
  （verify-boards 有塌陷检测，但设计时就要保证）。〔同一事故：命中/axe/碰撞三层全免疫〕
- **D5b 内容地板 ≠ 拖拽下限 ≠ 默认零溢出**(2026-09-22 名称列两轮教训: 先截断、后"拉不动"):
  ①"默认态不截断"由默认宽保证,按单元格自身必要内容推导(文字+全部随行 chip+间距);
  ②**拖拽下限必须远低于内容地板**——用户主动收窄是用户的裁决权,截断由 title tooltip 兜底,
  把内容地板写成拖拽钳制等于没收用户的宽度控制权;③弹性列(fr)被用户拖过即"钉死"——
  fr 归零、余量显式转移给指定承接列,否则拖窄被 fr 重新吸收、拖拽形同虚设;
  ④默认(未拖拽)布局在对应档位容器内零横向滚动,横滚只能由用户主动拖宽触发
  (verify-boards 断言);⑤列集变更(加/删列)必须 bump 列宽持久化存储键;⑥格内牺牲
  次序显式声明(名称文字最后牺牲,附属 chip 先让位),不靠 flex 默认行为。
- **D5 盒子防御**：定宽容器装可变内容 → min-width + flex:none；行级信息不塞定宽构件内部。〔chip 溢出重叠事故〕
- **D6 i18n 完备**：新键 zh-CN 与 en-US 同时添加，禁裸键。〔tags.manage 裸键〕
- **D7 键盘可达**：Enter 确认、Esc 取消、点外关闭、Tab 移动。

### E 操作安全 —— 排产动作不能出事故

- **E1 防误触**：同值再点=无操作；破坏性操作二次点击确认；步进有上下限。
- **E2 失败可见可重试**：请求失败有反馈，不留半完成状态；按钮 busy 态防重复提交。
- **E3 可逆或可修复**：优先可逆设计（池可步进回、标签可再勾掉）；不可逆的要有确认与后果说明。
- **E4 并发/脏状态**：多标签同编辑不静默覆盖（至少冲突时提示）；部分失败不写脏数据。

## 视觉战术速查（Refactoring UI 摘要，仅收本项目适用的）

生成与审查 UI 时的战术镜头，与五支柱正交（都服务于 D 呈现健壮 / B 语义透明）：

1. **层级用字重与颜色，不用字号堆叠**——本项目已固化 --b-fs 三档（14/12.5/11），
   字号档位守卫 ≤6；再要强调时改字重或压深，不加第四档字号。
2. **灰字不能过灰**——次要文字保持可读对比（浅色主题 #374151 级）；disabled 态
   也要可辨认其存在。〔浅色徽章发虚事故同源〕
3. **间距成体系**——4px 栅格倍数，不出现随机值；守卫的水平分隔线/圆角/字号档位
   断言即此战术的机器化。
4. **少用重边框，用间距、底色、阴影分区**——组头底色+行分隔线，不加框套框。
5. **主色只强调一处**——工具栏仅"新建"用主色按钮，其余幽灵化。
6. **深色不是浅色取反**——两主题各自调对比（双主题渲染契约已固化）。
7. **表格数字等宽右对齐**（tabular-nums 已全站使用）。
8. **状态色饱和度克制**——文字态用压深色不靠亮底色。〔8 态徽章浅色压深经验〕

## 布局边界契约（2026-11-10，收件箱录入按钮 hover 越界事故沉淀）

三条物理契约（不是审美偏好）——违反即产生"上沿被截断/控件不齐"的可见事故：

1. **页面顶边呼吸**：tab 内容区首行与 tab 栏之间必须 ≥8px（`--page-top-gap`，由 `UnifiedTabComponent` 统一提供），页面不得自己贴边——悬停位移/阴影需要落点。
2. **同排控件等高**：同一 toolbar/filters 行内的按钮/输入/下拉必须同高（`--button-min-height`/`--input-min-height` = 40px；44px 只用于独立图标钮）。只有更高的那个会顶到容器边界并在悬停时越界。
3. **按钮不做 hover 位移**：禁止在 `:hover/:focus` 上改变 `transform/translate/scale/padding/margin/height/top/left…`（尤其未作用域 `.btn*`/按钮/链接类覆盖——随路由 CSS 加载泄漏到同路由所有按钮）。旧式"padding+负 margin 外扩"默认禁止（会被 `overflow:hidden` 裁切，roadmap 项目名链接实测）。悬停用底色/描边/下划线/阴影表达。卡片类 elevation（card/stat/insight/summary…）不在拦截面。
   `npm run lint:ui` 规则 4（未作用域 `.btn*` 位移）+ 规则 5（交互态布局几何）静态拦截；`verify:states` 新机制切片（悬停/焦点位移×容器边界、同排控件等高）渲染时刻兜底，`--selftest` 注入必红。

## 交互与状态判据（judged 层）

来源：UI UX Pro Max 120 条清单 gap 分析（2026-11-14 调研，节尾 pin）。条目格式：
**ID〔权威标签〕规则 — 实施状态**。权威标签的执行语义（I03g 裁决）：
〔规范〕违反即阻塞（评审 P1 起）；〔半规范〕豁免须留痕（证据+理由）；〔风格〕默认非阻塞、偏离需一句话说明（适用时仍须检查，不得静默跳过）。严重度沿用 P0–P3 用户影响定义，不另造体系。

1. **IX-1〔规范〕输入法组合态**：文本输入上的 Enter 提交/失焦保存必须判
   `isComposing`/229（中文/日韩输入法的 Enter 是"确认候选词"）。共享原语
   `client/src/lib/ime.ts`；守卫 `tests/unit/meta/ime-enter-guard.test.ts`。
   实施：已修补 14 文件；**扫描器四漏检已证**（双引号 Enter/守卫名入注释即放行/
   守卫调用被忽略/白名单整文件豁免）——修漏检前此条为 ⚠️，修后转 pre-commit。
2. **IX-2〔规范→项目策略〕首错聚焦**：表单提交失败时聚焦第一个非法字段
   （`aria-invalid` 优先）。注：WCAG 3.3.1 只要求错误以文字识别/描述、3.3.3 为
   条件性 AA 建议——**首错聚焦是本项目实施策略而非标准原文**；错误摘要（多错
   汇总+链接）已裁决不做（≤2 字段表单摘要=噪音）。实施：待接通真实错误路径
   （QuickCaptureDialog 字段错误→aria-invalid→聚焦，非字段错误聚焦告警区）。
3. **IX-3〔规范〕路由切换焦点**：SPA 导航后焦点移到主内容区。注：WCAG 2.4.3
   约束的是焦点顺序合理性，"导航聚焦主区"是本项目的实现约定（可被组件测试证明
   的是项目行为，不是 WCAG 合规证明）。实施：待做（测试须含懒加载/查询参数变化/
   页面自身有意聚焦时不覆盖）。
4. **IX-4〔风格〕截断提供全文**：优先换行；必须截断时全文可达。**title 属性不
   是充分实现**（键盘/触屏不可达，HTML 标准明示）——验收对象是"实际截断内容的
   访问路径"（展开/悬浮可达/静态化减免），不是 title 计数。实施：tsx truncate
   11 处 0 处可达，欠账；处置=lint 静态化（truncate 必须伴随展开/悬浮机制）+
   高频页人工补，不以欠账删规则。
5. **IX-5〔风格〕只读的可解释性**：不可编辑的原因对用户明确，不把只读伪装成
   禁用控件。原"视觉不可共用灰化"绝对化表述删除（Codex：readOnly 命中多为
   `readOnlyWindow` 业务属性非只读输入；静态文本渲染无须 aria-readonly）。
   实施：观察项（一次性审计后定去留）。
6. **IX-6〔半规范〕加载与布局稳定**：>1s 用骨架（按来件形状）；异步内容预留
   尺寸防 CLS；50+ 项评估虚拟化。实施：骨架仅 2 源文件（skeleton 原语+
   ProjectDetail），观察项逐步扩。

## 数据可视化契约（judged 层）

守卫（对比度/重叠/溢出/axe）判不了的**读图正确性**，评审按以下八条判。来源：Hallmark
`data-viz.md` / `flow.md` app screens（v2.0，2026-11-14 读取；语境改写处逐条注明）。

1. **DV-1〔半规范〕一图一 Y 轴**——同一图表两套刻度伪造相关性；两个单位=两张
   小多图。**现行违规**：泳道热区同屏渲染左刻度（pw-gantt-heat-scale 200/100/0）
   + 右刻度（pw-heat-axis 200/100）——I03g 修复后该提交即本条正例。
2. **DV-2〔风格〕强调只给一条序列**——"所有序列都响 = 都不响"。**语义切分
   （I03g 裁决）**：语义状态色（超载红纹/警示）与类别编码**不是**装饰性强调，
   不受"只强调一条"限制；本条限制的是**同一比较任务中的装饰性视觉强调**
   （谁加粗/谁变色/谁动效）。判定问句："去掉这个强调，读数会变吗？"不会=装饰。
3. **DV-3〔半规范〕基线语义**——依赖长度编码的图（柱/条）基线为 0，截断等同
   编造；确需非零基线或对数轴时显式标注"轴从 X 起"。折线趋势图不适用本条。
4. **DV-4〔风格〕形状服从数据**：单值→stat tile；2–5 值比较→横向 bar；时间
   序列→line/sparkline；>7 类→table；部分→stacked bar；禁 pie/donut/gauge/
   六卡 KPI 墙。6–7 类为空档：比较任务仍用 bar，浏览任务用 table。查表是默认
   建议不是硬规则，比较任务的判断优先于数量阈值。
5. **DV-5〔风格→本地裁决〕泳道 bar 构造（本地特例）**：工作负载泳道的 bar
   24px 高/≥24px 宽/26px 堆叠间距——**来源是 verify-states 命中下限（≥24px）
   与堆叠间距裁决，非 Hallmark 图表规范**（同数字反方向：那是营销图上限）。
   条内文字必须保持可读（tabular-nums）；其他图表的 bar 尺寸不引用本条。
   gridlines 1px 实线 3–5 条、文字不穿数据色仍为通用（Hallmark 语境改写）。
6. **DV-6〔半规范〕数据区四态**：loading（按来件形状的骨架）/ empty（这里该有
   什么 + 一个填充动作）/ error（坏了什么 + 怎么修）/ full——四态缺一即未完成。
   部分机器化：四态存在性组件测试证明的是"指定区域有四态"，不是全站证明。
7. **DV-7〔规范〕动效 = 状态**：不做滚动出现；动画只用 transform/opacity，
   不动 width/height/top/left。lint 可禁特定声明（transition:all 等），但
   "动效服务于状态"本身仍需评审判断。
8. **DV-8〔规范〕每个数字要么真实、要么显式"未配置/数据不可用"**——编造的
   序列比空槽更糟（与 A 支柱同源）。实施：已有（"未配置/数据不可用"双语言包）；
   触发=评审必填段。

app 屏幕旁证（Hallmark，语境引用）：密度即设计（控件 32–40 + 44px 命中区、
tables before cards）；**signature = 工具被记住的那个对象**（本项目即"工作负载
泳道"），评审时保护其注意力优先级。50 主题/照片库/hero/视觉身份不引入。

**裁决登记**：44px 触控 vs 泳道 bar 24px——bar 是数据展示件不是独立操作目标，
例外成立（G-01 评审裁决，斧触达下限 24px 已满足）；任务选择弹窗用模态——需要
保护焦点与多选上下文，符合"模态仅用于中断/保护焦点"（impeccable craft-floor）。

## 界面文案契约（judged 层）

来源：Anthropic `frontend-design` SKILL.md 写作纪律（main@2026-11-14 读取）。

1. **CP-1〔风格〕动作身份可追踪**：同一业务动作在按钮/进度/结果/撤销处保持
   **身份与对象一致**（不要求字面同词——"确认分配→已创建→撤销创建"是身份一致
   的正例，"Publish→Published"是同词正例；判据是用户能追踪"这是我刚才那个操作"，
   不是 i18n 键族或字面同词）。正例：确认分配链（assignments.json 同名族）。
2. **CP-2〔半规范〕错误 = 什么坏了 + 怎么修**，界面口吻，不道歉、不模糊。
   正反例：reconcile_missing 修复前裸码（"reconcile_missing"）/修复后
   （"提交结果未知：回读未找到匹配的已保存分配，请检查明细表后重试"）。
3. **CP-3〔风格〕空态 = 行动邀请**：说明这里该有什么 + 一个可执行动作，区分
   首次使用/无结果/筛选/权限。正例：IntakeInbox 空态三态分离。
4. **CP-4〔风格〕用户语言**：用户不需要理解内部字段名或错误码就能继续。
   判定问句："用户嘴上会这么说吗？"正例："未配置"≠`source=unconfigured`。
   （原"每个元素只做一件事"半句移除，另归信息密度裁决。）

**密度裁决登记**（防反向误用"反 AI 套话"清单）：表格/泳道内用 `·` 拼接 meta
（"项目 · 角色 · 40%"）、`→` 表示日期区间，是**有理由的密度压缩**，不视为模板化缺陷；
表格之外的装饰性 meta 串/箭头后缀/全大写标签/眉标逐步减少。裁决须在评审记录里可追溯。

## 默认色板（Okabe-Ito 色盲安全八色）

侧点、状态色、标签默认色的统一来源（用户自选标签色时以此作为默认选项）：

`#E69F00 橙 | #56B4E9 天蓝 | #009E73 绿 | #F0E442 黄 | #0072B2 蓝 | #D55E00 红橙 | #CC79A7 粉紫 | #000000 黑`

用法约定：色只做**类别编码**（哪一侧/哪个状态），不做量值编码（量值用数字与长度）；
同屏并用的类别色 ≤4 个，多了退回灰阶+文字标签。

## ② 认知走查（交付闸，跑守卫之前）

Cognitive Walkthrough（认知走查，Polson/Wharton，可用性工程标准方法）：以第一次
见到此页面的人视角，沿真实任务逐步走（双主题渲染，逐个打开本次涉及的全部交互，
**含同页被波及的旧交互**），每步四问：

1. **用户此刻想产生这个效果吗？**（控件出现在任务的正确环节）
2. **用户能看到这个操作吗？**（物理呈现：图标、标签、悬停提示）
3. **用户能把操作和效果联系起来吗？**（不看文档知道它在改什么、范围、后果）
4. **操作后用户能看到反馈吗？**（值变了/受影响的量动了/失败了会怎样）

四问有一个"否"即回到维度清单修，不进守卫环节。

## ③ 守卫（兜底）

- `npm run lint:ui`——CSS 反模式静态扫描（定宽按钮无 padding 等），生成时秒级，`SELF_TEST=1` 自证
- `npm run verify:states`——全称状态检查器（自动枚举全部可见交互元素，真实指针强制状态，双主题断言对比度/命中/遮挡/越界/字号/浮层贴锚；已收编进 verify-boards 交付闸；`verify:states:selftest` 注入必红防恒绿）
- `npm run verify:boards`——结构+几何+可供性断言（图标物理可见、塌陷检测、池标签、编辑模型声明；尾部 spawn verify:states）
- `npm run verify:visual`——像素基线 + axe 预算 + 碰撞，双主题×双视口
- 单测——交互语义与落库

|---|---|---|
| FMEA（失效模式与影响分析） | 汽车/航天可靠性工程 | 生成前协议第 1 步：支柱失效排查表（从功能推失效，非从事故推） |

| 启发式评估（Nielsen 十启发式） | 可用性工程 | 守卫的镜头来源：碰撞/物理可见/一致性/防错/状态可见各对应启发式的机器化；单评估者覆盖率有限，守卫按镜头分遍跑即为对策 |
| Poka-yoke（防错法） | 丰田生产系统 | 已有实践命名归位：同值无操作、min-width 代替 width、padding 同块重置、步进上下限、二次点击确认 |

| BDD/规格先行（Given-When-Then） | 敏捷工程实践 | 交互功能先写验收例再生成——单测先行已是其形态，契约点名归位 |
| Refactoring UI 战术 | 开发者向 UI 设计（Wathan & Schoger） | 视觉战术速查八条（层级靠字重/灰字不过灰/间距成体系/少框/主色一处/等宽数字/状态色克制） |
| Okabe-Ito 色板 | 色觉无障碍科学 | 默认色板：类别编码专用，同屏 ≤4 色，量值不用色 |
