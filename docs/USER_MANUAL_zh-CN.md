## 1. 系统是什么

Capacinator 是一个**团队资源容量规划工具**,回答管理者最关心的几个问题:

- 手头有多少人、什么角色,各自还剩多少产能?
- 每个项目什么时间段需要哪些角色、多少人力(FTE)?
- 把人派到项目上后,谁超负荷了、谁还闲着?
- 如果换一种人员安排方案(增派/裁撤/换人),结果会怎样?

系统的数据主线是:**地点 / 角色 / 项目类型(阶段模板)→ 人员 → 项目(阶段)→ 分配(人×项目×角色×比例)**,所有查看与编辑都在某个"场景"下进行。

## 2. 访问与登录

### 2.1 打开系统

- 浏览器(推荐 Chrome/Edge)访问:**`http://<服务器IP>:3120`**(当前部署:`http://192.168.3.19:3120`)
- 页面打不开时:确认本机与服务器网络互通、服务器防火墙放行 3120 端口

### 2.2 选择身份登录

系统**没有账号密码**。首次打开会弹出「**选择你的身份**」对话框:

1. 在「你是谁?」下拉里选择你的名字(显示为 `姓名 (主角色)`)
2. 点击「继续」

选择会保存在浏览器本地,下次自动登录。**身份决定两件事**:你的操作权限(是否系统管理员),以及审计日志里"谁做的修改"。切换身份:点右上角姓名 → 退出登录。

### 2.3 语言与主题

- **语言**:顶栏右上角「中 / EN」按钮一键切换;也可在 设置 → 外观 → 界面语言 切换。首次访问自动跟随浏览器语言,选择会记住。
- **深浅色**:顶栏 🌙/☀️ 按钮切换。
- **场景切换器**:顶栏中央(分支图标)—— **这是全局开关**,切换后所有页面的数据都切换到所选场景下,详见[场景](#55-场景)。

## 3. 核心概念

| 概念 | 英文 | 说明 |
|---|---|---|
| **场景** | Scenario | 一套独立的规划数据。**基线(Baseline ★)** 是正式计划;**分支(Branch)** 从某个场景复制一份来做试验;**沙箱(Sandbox)** 从零开始。顶栏选择器决定你当前在哪个场景下工作。 |
| **分配** | Assignment | "某人,以某角色,在某项目(某阶段),从某日到某日,投入 N%"。这是系统最核心的数据。 |
| **分配比例 / 利用率** | Allocation / Utilization | 分配比例是单条分配的投入%(如 50% = 半工时);利用率 = 某人所有有效分配之和 ÷ 可用率。**>100% 超负荷(红),≥80% 满负荷(黄),<40% 空闲(绿)**。 |
| **项目类型与阶段模板** | Project Type / Phase Template | 每类项目(如"Web 应用")定义标准阶段流(BP→DEV→SIT→UAT→CUT→SUP)和各阶段的时长、角色配比模板。新建项目时自动套用。 |
| **财周** | Fiscal Week | 格式 `24FW36` = 2024 财年第 36 周(财年从 9 月起)。用于 Excel 导入的路线图/需求列。 |

**权限模型**:按角色(带优先级)+ 系统管理员 + 个人权限覆盖。当前版本权限页为只读展示;日常操作以实际按钮是否可用来感知权限。

## 4. 快速上手

**第一次使用,推荐按这个顺序(约 10 分钟):**

1. **登录** → 选一个身份(演示数据里如 Alice Johnson)
2. **仪表盘** → 看四张统计卡和 KPI,了解全局(当前场景的数据)
3. **人员** → 看团队 workload 分布;点某行「查看详情」看个人的分配时间线
4. **项目** → 点开一个项目看阶段时间线和团队成员
5. **分配** → 试建一条分配:+新建分配 → 选项目/人/角色/比例/日期 → 保存,回人员页看该人利用率变化
6. **场景** → 从基线建一个分支,删掉两条分配,切到分支再回仪表盘——数据变了,而基线原封不动
7. **报表** → 分别看 需求 / 产能 / 利用率 / 缺口 四张报表
8. 想重来?**导入导出页**下载空模板,或执行 `npm run db:seed` 恢复演示数据

## 5. 页面详解

### 5.1 仪表盘

一屏看清当前场景的全局健康度。

**顶部四张统计卡**:进行中项目 / 总人数 / 角色数 / 产能缺口数(红色,点开进报表)。每张卡可点击跳转。

**四个增强 KPI(带目标值与进度条)**:

| KPI | 含义 | 目标 |
|---|---|---|
| 资源效率 | (满负荷人数 − 超负荷×0.5)÷ 总人数 | 85% |
| 项目健康度 | 活跃×1.0 + 规划中×0.7 − 逾期×0.5 | 80% |
| 产能消耗率 | (缺口角色 + 紧张角色×0.8)÷ 总角色数,越低越好 | 70% |
| 分配准确率 | 未超负荷人数占比 | 95% |

**关键告警面板**:自动检测 6 类问题——产能缺口严重、人员超负荷、项目逾期、团队利用过高(>80% 人员满负荷)、角色产能紧张、近期人力缺口——每条可点击直达对应报表处理。无告警时显示"系统状态正常"。

**四张图表**:项目健康分布(饼图)、资源利用分布(柱图)、各角色产能状态(缺口/紧张/正常,可点击)、快捷统计(可用/休假/受限/超负荷人数)。

> 注意:顶部日期范围选择器主要起视图标注作用,仪表盘数据按"当前时点"计算。

### 5.2 项目

入口:侧边栏「项目」。页面有三个标签:**项目列表 / 项目类型 / 路线图**(URL 中 `?tab=` 可直达)。

#### 项目列表
- 筛选:搜索、状态(已计划/进行中/已暂停/已完成/已取消)、项目类型、地点
- 列:项目名、类型、状态、优先级、地点、起止日期、负责人等;点行进详情
- **新建项目**:+ 新建项目 → 填名称、类型、地点、优先级、负责人、外部 ID 等 → 保存时**自动套用该类型的阶段模板和默认起止日**
- 删除:行操作 → 确认对话框(需二次确认,不可恢复)

#### 项目详情页
- **基本信息**:点击字段直接行内编辑(名称、描述、状态、优先级等)
- **阶段时间线**:该项目的各阶段(名称、颜色、日期);可编辑日期、增加自定义阶段(受模板合规校验约束)
- **团队分配**:当前项目上的所有人、角色、比例、日期;可在此直接添加/移除分配
- **项目需求图表**:需求 vs 产能 vs 缺口三个视图切换,时间粒度(日/周/月/季)可调,支持时间刷选择区间

#### 项目类型(标签页)
- 列表/层级两种视图;类型和子类型(子类型继承父类型的阶段与配比,可覆盖)
- **类型详情页**是配置核心:
  - **阶段模板设计器**:增删排序阶段,设置每阶段 是否必选/顺序锁定/默认·最小·最大天数
  - **角色配比矩阵**:角色 × 阶段 的分配% 表格(如 PM 在 BP 阶段 50%),新建项目时自动继承这些值

#### 路线图(标签页)
所有项目的甘特式总览:每行一个项目,彩色阶段条;支持**拖拽调整阶段起止**、双击精确输入日期;缩放、按月滚动、「今天」红线定位;搜索与状态筛选。**阶段日期改动会自动联动"阶段对齐"的分配**。

### 5.3 人员

入口:侧边栏「人员」。三个标签:**人员 / 角色 / 可用率**。

#### 人员列表
- 顶部快捷统计:「N 人超负荷 / N 人空闲 / 共 N 人」
- 列:姓名(邮箱)、主角色、类型(FTE/合同工/顾问)、地点、可用率%、日工时、**工作负载**(超负荷/满负荷/负荷不足/空闲 + %)、快捷操作
- **快捷操作按状态智能给出**:
  - 超负荷(>100%)→「减压」(跳转分配页减人)
  - 满负荷(≥80%)→「监控」(跳利用率报表)
  - 负荷不足(≥40%)→「增加分配」(**智能分配**弹窗)
  - 空闲(<40%)→「分配项目」(智能分配弹窗)
- 新建人员:姓名、邮箱、主角色、类型、地点、可用率、日工时、上级等

#### 人员详情页
可折叠分区:
- **负载洞察与建议**:总分配 vs 可用、利用率、活跃项目数、技能数、 upcoming 休假,以及按状态给出的**建议动作**
- **基本信息**(行内编辑)、**可用率与休假**、**角色与技能**(多角色,熟练度 1–5 级,标记主角色)
- **当前分配**列表(含是否计费)
- **分配 vs 可用图表**:堆叠时间线,超负荷区间标红,可拖拽缩放;显示峰值/均值
- **添加休假/不可用**:类型(休假/病假/培训/会议/其他)+ 区间 + 该期间可用率%(休假默认 0)+ 原因。**休假期间该人的有效产能取最严格值**,分配超出会记为冲突

#### 角色标签 / 角色详情
角色列表(搜索、按"有无规划者/有无人员"筛选)→ 角色详情:行内编辑名称描述、外部 ID;**资源模板矩阵**(项目类型 × 阶段 的分配%)——与项目类型详情页是同一份数据的转置视角。

#### 可用率标签
日历/列表两种视图管理所有人的不可用时段(休假/培训/部分可用/病假/其他),支持审批状态(已批准/待定)。

### 5.4 分配

入口:侧边栏「分配」。两个标签:**分配列表 / 推荐**。

#### 分配列表
- 筛选:搜索、项目、人员、角色、日期范围(当前/即将/过去/本月/下月)
- 列几乎全部支持**行内编辑**:角色(下拉)、比例(0–200,>100% 红色+⚠、≥80% 黄、其余绿)、起止日期、备注
- **日期模式徽章**:固定日期(可编辑)/ 阶段对齐 / 项目对齐 —— 后两者日期自动跟随阶段/项目,行内日期框禁用
- 删除需确认;从人员页"减压"跳转来时顶部有上下文提示条

#### 新建/编辑分配(弹窗)
字段:项目*、人员*、角色*、阶段(可选,限所选项目的阶段)、起止日期*、比例*(1–100)、**日期模式**(固定/阶段对齐/项目对齐)、备注、是否计费。
- 选了阶段且用"阶段对齐"后,阶段日期变化时分配日期自动重算

#### 智能分配(Smart Assignment)
从人员页快捷操作或人员详情打开,标题「✨ 为 {某人} 智能分配」,顶部显示当前利用率/剩余产能/活跃分配数。两个标签:
- **推荐分配**:按角色匹配度打分的候选项目卡(完美匹配/良好匹配/部分匹配 + 推荐理由 + 建议比例),点选后下方出现影响预览(总分配将变为 N%、是否超配)
- **手动选择**:只列**有资源缺口**的项目 → 角色限定为该项目所需 → 阶段限定为缺该角色的阶段;选阶段后日期自动锁定联动;比例用滑杆(步进 5%),提示剩余可用
- 若从"减压"入口进来,手动标签变为**移除分配**清单

> 「推荐」标签页当前为占位实现(服务端返回空列表,显示"暂无推荐"),实际可用的推荐能力就是上面的智能分配弹窗。

### 5.5 场景

入口:侧边栏「场景」。这是做**规划实验**的地方。

#### 场景树
以层级树展示所有场景:名称 / 类型(基线★·分支·沙箱)/ 状态(活跃·已归档·已合并)/ 创建人 / 创建时间 / 操作。支持搜索、按类型/状态/创建人筛选、「隐藏已合并」快捷开关。

#### 建场景
- **+ 新建场景**:填名称、描述,选类型(分支/沙箱)
- **从某场景建分支**(行操作 ⇩):自动以该场景为父,复制其全部分配与阶段数据
- 基线场景不可删除;删除其他场景需**输入场景名确认**

#### 对比(行操作 ⇄)
选另一个场景 → 运行对比:分配的新增/修改/删除明细 + 影响分析(总分配比例变化 ±N%、净分配条数、受影响项目数)。

#### 合并(行操作 ⤴)
把分支合回父场景(仅"有父且活跃"的分支可用):
1. **冲突策略**:偏 source(推荐,分支改动优先)/ 偏 target(父场景现状优先)/ 手动逐条(高级)
2. 勾选确认(不可撤销,分支将标记为已合并)→ 合并

> 选"手动逐条"时如检测到冲突,系统会暂存冲突并提示需手动处理;当前版本的界面上手动解决入口尚未开放,建议优先使用"偏 source/偏 target"。

#### 场景与全局数据的关系
顶栏场景选择器切换后,项目/人员/分配/仪表盘/报表全部按所选场景取数——**分支里的改动不影响基线,合并时才落地**。所有 API 自动携带场景 ID,无需额外操作。

### 5.6 报表

入口:侧边栏「报表」。四个标签:**需求 / 产能 / 利用率 / 缺口分析**。共享筛选:起止日期、项目类型、地点、刷新;右上「导出」→ CSV / Excel / JSON。

| 报表 | 回答的问题 | 关键内容 |
|---|---|---|
| **需求** | 项目要多少人? | 总需求工时、有需求的项目/角色数、峰值月;按项目/按角色的需求图、月度趋势;高需求项目与角色 TOP5 |
| **产能** | 团队供得起吗? | 总产能工时、人均产能表(日工时、可用率、状态徽章)+ 行操作(分配/减压/详情);角色产能分析(已用/剩余工时,利用率 ≥90% 危急、≥70% 偏高) |
| **利用率** | 人用满了吗? | 平均利用率、超载/不足/最优人数;按人/按角色利用率图 + 分布桶(0-50/51-79/80-100/>100);团队明细表带进度条和"减压/加项目"操作 |
| **缺口分析** | 差多少?补哪里? | 总缺口工时(红)、有缺口的项目/角色数;缺口趋势;**可操作清单**:缺口严重的项目(仅 N% 覆盖 → 加资源)、缺口严重的角色(缺 N 小时 → 招聘/调岗),以及覆盖良好的项目与角色 |

报表顶部显示当前场景名(分支会注明来源),数据同样随顶栏场景切换。

### 5.7 导入导出

入口:侧边栏「导入导出」。两个标签。

#### 导入(Excel)
1. 顶部两个开关:**导入前清除现有数据**(慎用,会全量重置)、**使用新模板格式(财周)**(默认开,V2)
2. 「导入配置」卡片显示默认规则(来自设置),「高级设置」可对本次导入单独覆盖(去重校验/自动建角色/自动建地点/默认优先级/日期格式)
3. 把 `.xlsx/.xls` 拖入上传区 → 「上传并导入」→ 进度提示 → 结果面板
4. 结果:成功/失败 + **导入统计**(地点/类型/阶段/角色/人员/项目/分配/需求…各类条数)+ **错误与警告清单**(精确到"工作表·行·列:原因与修改建议")

**模板从哪来**:本页「导出」标签 → 下载空白模板(完整/基础/极简三档,含说明行和示例行,导入前删除示例行)。`test-data/` 目录也有现成示例文件可直接练手(推荐 `simple-test-data.xlsx`、`sample-data-template.xlsx`)。

**V2 财周模板要点**:工作表包括 项目类型、角色、Roster(名册)、项目、项目路线图(财周列 `24FW36`…,阶段缩写见附录)、资源模板;可选 项目阶段/标准分配/项目需求/项目分配。项目名支持 `项目名 @ 地点` 写法自动挂地点。导入在**单事务**中执行,任一错误整体回滚;开启去重校验发现重复即中止。

#### 导出
- **导出场景数据**:选场景 → 可选包含项目分配/阶段时间线 → 下载 `<场景名>_export_日期.xlsx`(含元数据页,可直接再导入)
- **下载空白模板**:三档模板定制
- 报表页的导出(见 5.6)独立于本页

### 5.8 地点

简单的字典维护页:添加/删除地点,名称与描述**点表格即改**(行内编辑)。地点用于人员归属、项目归属、人员与报表的地点筛选,以及按地点的产能统计。

### 5.9 审计日志

入口:侧边栏「审计日志」。所有数据变更自动留痕:

- 筛选:数据表(人员/项目/角色/分配/可用率)、操作(创建/更新/删除)、操作人、记录 ID
- 表:时间、数据表、操作徽章、操作人(默认"系统")、变更字段
- **详情展开**:请求 ID、IP、User-Agent、备注,以及**旧值/新值 JSON 对照**
- **撤销**:对非删除操作可「撤销」该记录最近一次变更(需确认)
- 统计卡:总条目、日期范围、按操作/按表的分布

## 6. 典型工作流程

### 流程 A:新项目立项并配人
1. 项目 → 新建项目(选对类型,自动带出阶段模板与角色配比)
2. 在项目详情 → 阶段时间线校准各阶段日期(或去路线图页拖拽)
3. 项目详情 → 团队分配 逐条添加(或用人员页智能分配反向找人)
4. 人员页/报表页确认没人被压超;超了就调比例或换人
5. 仪表盘确认告警清零

### 流程 B:做一轮"如果…会怎样"实验
1. 场景 → 从基线「创建分支」(如"Q4 乐观方案")
2. 顶栏切到该分支 → 随意增删改分配、调阶段
3. 场景页「对比」基线 vs 分支 → 看影响分析
4. 满意 → 「合并」回基线(偏 source);不满意 → 删除分支
5. 切回基线继续正式计划

### 流程 C:从 Excel 迁移存量数据
1. 导入导出 → 导出标签 → 下载空白模板(完整版)
2. 按模板整理数据(路线图用财周列;示例:24FW36 列填阶段缩写)
3. 设置 → 导入:确认默认项(首次迁移可勾"导入前清除现有数据")
4. 导入标签上传 → 检查错误清单逐行修正(有错整体回滚,不会导一半)
5. 仪表盘/报表验证数据合理性

### 流程 D:处理能力缺口
1. 仪表盘告警「产能缺口」→ 点进缺口分析报表
2. 看"缺口严重的角色"(缺多少小时)与"覆盖不足的项目"
3. 对策三选一:人员页给闲的人「增加分配」/ 调整项目阶段时间错峰 / 招聘(缺口报表直达)
4. 回仪表盘确认缺口数下降

## 7. 常见问题与已知限制

**Q:为什么看不到任何数据?**
A:三个可能——① 数据库为空(执行 `npm run db:seed` 灌入演示数据);② 顶栏选中的场景没有数据(切回基线);③ 筛选条件太严(清除筛选)。

**Q:分配比例能超过 100% 吗?**
A:单条分配上限 100%;同一人合计可超(表内 >100% 显红⚠)。是否"允许超配"及上限(100–200%)在 设置→系统。注意:界面的红色阈值固定按 100%/80% 显示,不随设置的上限变化。

**Q:改了阶段日期,分配日期没跟着动?**
A:只有**日期模式 = 阶段对齐**且关联了阶段的分配才会自动联动;固定日期的分配需手改。

**Q:两个场景数据会互相影响吗?**
A:不会。基线之外的场景改动写入独立场景表;只有显式「合并」才写回父场景。

**Q:误操作能找回吗?**
A:审计日志对创建/更新类操作提供「撤销」;删除类不可撤销(操作前的确认框即为最后防线)。重要实验请放在分支场景做。

**已知限制(当前版本),遇到时不必疑惑:**
- 分配页的「日历视图」按钮会跳回列表(目标路由未实现)
- 分配页「推荐」标签为占位(始终为空);推荐能力在人员页的智能分配弹窗
- 场景合并选"手动逐条"后,界面上暂无逐条解决冲突的入口(用偏 source/target 策略)
- 仪表盘日期范围选择器不改变底层数据口径(按当前时点计算)
- Git 同步(GitHub 分支/推送/拉取)为实验特性,默认关闭(设置→GitHub 可连账号)
- 设置→用户权限为只读展示,角色/权限的修改需管理员在服务端配置
- 阶段依赖编辑(FS/SS/FF/SF)后端已支持,前端界面尚未开放

## 附录:项目评估与死线校验(第 1 步功能,2026-09 上线)

入口:**项目详情页 → 「评估」折叠区块**(位于"团队分配"与"历史记录"之间)。

### 1. 录入评估

| 字段 | 说明 | 默认值 |
|---|---|---|
| 预估代码行数 | SE 初步识别的规模,如 15000 行 | 必填 |
| 换算率(行/人月) | 0.5k 行/人月即填 500 | 500 |
| 设计占比 % | 设计(含需求分析)占总人月的比例,先用占位值,评审后修正 | 15 |
| 乐观/悲观偏差 % | 输出区间用:乐观 ×(1−乐观%),悲观 ×(1+悲观%) | 20 / 50 |
| 期望交付日期 | 死线校验的默认死线 | — |
| 评审备注 | 小会评审结论等 | — |

填写时下方**换算预览实时刷新**:总人月 / 设计人月 / 开发人月三行区间(乐观 ~ 悲观)。每次「保存评估」生成一条新记录,评估历史保留、最新一条为当前评估。

### 2. 死线校验(一键)

点击「死线校验」(如录入了期望交付日期会自动使用),系统立刻输出:

- **整体结论徽章**:可行(悲观口径也够)/ 紧张(乐观口径刚好、悲观不够,风险区)/ 不可行(连乐观口径都缺人)
- **两侧明细表**:设计侧(SE)与开发侧的需求人月区间、窗口内空余人力、缺口(-)或余量(+)、各自结论
- **口径脚注**:空余人力 = 每人可用率 − 窗口内已有分配(含问题单 30%、事务 25% 等预留缓冲),不含本项目自身;1 人月 = 1 人在 100% 可用率下投入 1 个自然月

结论为"不可行"时的处置选项(人工决策,系统不改数据):降范围(减行数)、延死线、加人/调缓冲——这些权衡在第 2 步"排期沙盘"中会做成对比推演。

### 3. 交付后回填

交付后在同一区块录入:实际代码行数、实际设计人月、实际开发人月、实际交付日期。保存后系统自动算出**估算偏差**(行数/设计/开发各一个百分比,正=实际超估算)与**延期天数**。积累几条后,即可据此修正换算率与设计占比默认值,让后续评估越来越准。
