# 高频操作性能预算（IP-09 / §4-322）

**实测基线**：2026-10-21，HEAD `8a383b1`，生产构建（vite build + preview 代理），Chromium 1600×900，zh-CN，
隔离 e2e 库受控规模。两档：**基线档 30人/15事/60分配** 与 **压力档 ×3 = 90人/45事/180分配**（各含 SR×2→AR×2 树与 1 个 branch 场景）。
每操作 5 轮采样；复跑：`npm run perf:ops`（数据追加 `perf-history.jsonl`，`kind:"ops"`）。

**口径（诚实边界）**：
- "交互窗口" = 动作 → DOM 条件成立 + 网络静默 + 固定退避（搜索 600ms、展开 300ms）——是**上界**而非纯交互延迟。搜索/展开的 p50 主要由固定退避垫底；无 long-task（0 次 ≥50ms 主线程阻塞）佐证交互本体远小于窗口值。
- 筛选/搜索/展开/换方案 **0 网络**：React Query 缓存 + 客户端过滤/树展开，不产生 API 往返——请求量预算天然满足。
- ×3 档与基线档全指标无退化（虚拟化行渲染 + 客户端缓存的直接收益）。

## 预算线（p95 实测 × ~1.5 取整；回归即破线复查）

| 指标 | 预算 | 依据 |
|---|---|---|
| 筛选（chip/搜索）交互窗口 p95 | ≤ 1000 ms | 实测 ≤679（含退避常数） |
| SR 展开 p95 | ≤ 600 ms | 实测 ≤401 |
| 换方案 p95 | ≤ 200 ms | 实测 ≤116 |
| 批量调整 p95 | ≤ 2000 ms | 实测 ≤1332 |
| 高频读操作 API 请求量 | ≤ 2 / 操作 | 实测 0（缓存命中） |
| 批量写 API 请求量 | ≤ 8 / 操作 | 实测 ≤4（PATCH+失效重取） |
| 任何高频操作 long-task (≥50ms) | ≤ 2 次 / 操作 | 实测 0 |
| API 响应 p95（本地 sqlite，小载荷） | ≤ 200 ms | 实测 ≤24 |

预算意图：这些线是**回归哨兵**而非优化目标——当前值全部远离预算线；破线说明缓存策略/虚拟化/查询发生了退化，先查变更再调线。
