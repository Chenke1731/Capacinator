## 1. 目标与已裁决约束

服务 10–30 人团队的人力主管，提前看见 SE/开发缺口，使一次排产决定可解释、可执行、可追溯。依据是 [真实需求](../REQUIREMENTS_zh-CN.md)、[需求台与迭代设计](../BOARD_REDESIGN_2026-09-23.md) 和 [UI 契约](../UI_GENERATION_CONTRACT.md)。

实施必须保留：

- 人月表达事情工作量，占用百分比表达人员负荷；按已裁决的约 21.75 工作日/月折算工作月。
- 占用比例是写入时的快照，不能随着今天的变化静默重算；重估需显示差异并由人决定。
- 人决定生命周期流转，系统建议式告警；不得擅自恢复硬性审批或流程门禁。
- 迭代挂接等是共享事实，当前沙盘主要试验人力分配；扩大沙盘范围须先修改领域设计。
- 标签用于筛选与分组，不增加隐藏计算语义。
- 没有工时填报，计划推定快照与人工实际必须区分；校准采用轻量回填与间接信号。
- 保留现有事务、外键、主投入唯一约束、停用机制、缓存键守卫和已验证的交付红线。
- SE/MDE分量粗估与详情页设计总量目前有意分开维护（[实施日志D5](../BOARD_REDESIGN_IMPL_LOG.md)）；收口分析入口应明确采用哪个评估及覆盖哪些侧别，不能直接覆盖总量或把两种估算相加。
- 迭代强度v1允许窗口平均口径；本轮R05纠正SE所用窗口，不以增加逐日峰值作为该修复的必要条件。多事自动排期属于需求第2步，先修已有数字与结论表达，再按试运行价值实施。

## 2. 证据分级与本轮复现

**A：隔离复现。** 调用实际服务/控制器实现，用临时 SQLite `:memory:` 数据或纯函数输入，未接触真实库；浏览器探针使用实际页面并拦截写请求。简化 schema 只证明所审查询与算法，响应夹具只证明页面状态/请求关系，均不能替代真实迁移、完整 HTTP 或正式部署验收。控制器探针绕过HTTP/错误包装并等待响应完成；月账使用人为同步点强制请求交错。

**B：代码确认。** 路由、调用链、写入字段和数据库默认值已核对，尚未完成完整流程复现。

**C：设计/试运行项。** 不作为已发生缺陷；通过明确裁决或真实使用观察再决定实现。

### 2.6 四角色的判断与边界

| 角色 | 当前最需要回答的问题 | 可交付的改进结果 |
|---|---|---|
| 人力主管 | 接受A后，B还能否执行；重排实际腾出了哪个窗口的哪种产能？ | 同窗口的受影响事项、角色缺口和替代方案；先支持人工比较，不必先做自动最优排程 |
| SE | 这次判断采用我的哪个估算，含分析/评审还是MDE；为什么一处显示50%、另一处赶不上？ | 估算来源、用途、角色窗口及是否仍为占位值可辨；合法0不被替换，重复维护成本可观察 |
| 交付负责人 | 前置设计真的来得及；结果是讨论输入还是已定承诺；变化后还能沿用吗？ | 节点/范围说明、依赖与未知项、已选方案及重新校验条件；保持人工流转权 |
| 独立计算审计者 | 月总量相同但时间重叠时能否发现冲突；同一份产能是否被重复用于组合结论？ | R01–R08的独立结果断言、版本上下文及可人工核算输入，不以接口200或截图漂亮替代正确性 |

## 3. 执行顺序与工作包

优先级含义：P1=会改变真实判断、数据或动作结果，应先修；P2=提升决策效率与可维护性，在相关P1闭环后推进。每个工作包独立提交；本计划的checkbox代表实施验收，当前均未完成。

| 工作包 | 优先级 | 交付结果 | 依赖与安排 |
|---|---|---|---|
| IP-01 | P1 | 可信的业务样例与真实schema验证入口 | 首批；服务于所有工作包 |
| IP-10 | P1/P2 | 共享API契约、类型与工程治理 | 结合IP-01；U04等相关端点先做，完整迁移渐进进行 |
| IP-02 | P1 | 统一时间窗口、工作月与有效分配读取 | IP-01；先收口计算来源 |
| IP-03 | P1 | 可用率与并发峰值正确的容量判定 | IP-02 |
| IP-04 | P1 | 保真场景分支、比较和原子合并 | IP-02；复制映射可先独立修 |
| IP-05 | P1 | 导入选择被尊重，预览与执行一致 | IP-01；可与计算修复独立推进 |
| IP-06 | P1/P2 | 发现问题到执行调整的UI闭环 | 失败反馈、跳转可先修；数字和预览依赖IP-02/03/04 |
| IP-07 | P1 | 实际回填不丢值、人工月账不被覆盖 | IP-01；可信操作者关联IP-08身份子项 |
| IP-08 | P1 | 恢复、身份与干净发布达到交付条件 | 可独立推进；正式交付还需相关业务工作包验收 |
| IP-09 | P2 | 人工采纳的校准建议、低成本数据维护 | IP-02/07；真实试运行在适用交付条件满足后 |

### IP-01：把业务反例转为真实结果验收

方向：以C01–C12为首批样例，新增R01–R08覆盖决策结论；固定日期、角色、场景、分配及人工实际，覆盖纯算法、实际查询与跨层旅程。修复迁移在测试环境的路径依赖，逐步用真实迁移建立隔离库，保留schema漂移守卫作为过渡。

- [ ] 针对每项拟修缺陷，先补能在当前实现上失败的实际结果断言，再实施修复；不以日志、返回200或空变更成功作为证明。
- [ ] 场景复制前后不改变基线，月桶工时守恒，缩小查询窗口不增加工时，暂停释放容量等不变量进入验收。
- [ ] 月账使用同步屏障制造交错；并发覆盖检测调用实际控制器或HTTP链，而非测试自建模拟类。
- [ ] 新集成入口从干净环境创建隔离库，可在CI运行；不借开发库或先存在的测试库。
- [ ] 保留现有unit/smoke/redline守卫；只扩大与本批变化相关的验证范围。
- [ ] 相关实施批次纳入阶段时序、重复容量预算、显式工作量、错峰变并发、SE窗口与长窗口、合法0、草稿版本反例；固定时钟，断言数值、日期及实际请求，而非只判断有告警/有变化（R01–R08）。

### IP-02：统一计算上下文与时间规则

方向：将“当前方案的有效分配”和“业务日期交集/工作日/月桶分摊”集中到领域模块，降低调用方对旧表、场景表和视图的知识依赖。明确请求上下文、单位、错误方式与数据来源，报告、死线校验、告警共用规则。

- [ ] 先求分配窗口与查询窗口交集，再计算工时；按各月真实工作日分摊，C01–C04通过。
- [ ] 单一场景读取，明确基线继承、覆盖、removed、paused及旧表去重规则；不把所有active方案加到一个人的负荷上，C05通过。
- [ ] 普通新分配写入后，列表、需求、报告及死线校验都能读取同一有效集合（F01）。
- [ ] UI显示场景、日期、单位与来源；共享事实与方案分配作用范围可辨。
- [ ] 原占用快照和历史估算保持原参数；规则升级先对比差异，不批量静默改写旧计划。
- [ ] 遗留模拟入口保留则接入真实计算与样例，否则明确不可用；占位数据不能得出“资源可行”的结论（F08）。
- [ ] 当前工作量读取规则在需求台、迭代、评估校验中一致或明确说明用途差异；开发人工覆盖参与对应分析，SE/MDE分量与设计总量不重复计算，保留D5规则及历史（R03）。
- [ ] 总量结论标明已验证侧别与节点；按事项实际约定显示设计节点、开发节点及串行/重叠/并行假设，未知依赖不默认已满足（R01）。
- [ ] SE使用开工前窗口、MDE/开发使用迭代窗口；同窗口工作日与告警一致，去除无说明的62天截断；已完成工作与剩余需求可辨（R05/R06）。
- [ ] 单项分析明确不预留产能、不代表组合可行；多事推演列入P2批次，共用每月容量预算，不把多次单项校验拼成组合结论（R02）。

- [ ] 可用率覆盖重叠时采用明确规则，公开假设；节假日表、跨池多面手供给分摊等扩展进入第5节裁决。
- [ ] 普通、批量、场景写入共用规则入口；允许超配的告警策略和硬拦截策略明确区分，保留现有人工裁决。

### 8.1 合成会议样例：总工时不变，关键窗口撞车

**性质：审视用样例，不是团队真实数据或已授权排产决定。** 直接采用R04的可核算输入：一名开发可用100%，本例没有其他分配/缓冲；两个事项A/B各需10个工作日，SE前置在样例中假设已确认完成。仅验证开发窗口可排性，不代表所有角色、范围与外部承诺均已核实。真实会议必须先确认SE/MDE、问题单/事务缓冲、休假及其他承诺。

|---|---|---|---|---|---|

| 候选方案 | 至少两种可执行的取舍；重排、降范围、借人、延期适用时逐一比较；无效方案写原因 |

| 已选方案及理由 | 明确选哪个，接受哪些代价，为什么其他选项没有采纳；属于条件决定时写条件 |
| 执行人与动作 | 谁负责修改哪些分配；涉及迭代、估算等共享事实须逐项标明；区分计划动作和已执行 |
| 执行核对 | 实际变化对象与比较预览一致，保存/合并失败不写已执行；保存提交/事件/审计引用 |
| 复核触发条件 | 估算/范围/迭代变化，SE未按前置节点确认，缓冲被挤占，休假/借入人变化；明确复核人 |
| 会议效果与维护成本 | 报表具体改变了哪个决定、下次复核结果、维护耗时和缺失数据；未实测保持空白 |

### 8.3 这轮审视后的处理次序

1. **立即纳入已有P1**：合法0、输入/校验版本、日期差异与受影响项目计数（R07/R08/R04）；结论的已验证范围说明（R01/R02/R03）。
2. **随计算收口交付**：开发人工覆盖与估算用途、SE窗口及告警、阶段容量、时间峰值对比（R03/R05/R06/R01/R04）。
3. **以真实会议决定P2范围**：先人工比较并记录一次真实取舍，再判断多事按月推演与记录界面是否值得建设（R02/R09）。自动排程、共享事实的方案化均另行裁决。

角色审视的关闭条件：有人能拿着同一份数据，解释“先做什么、谁在哪段时间投入、被挤占什么、哪些结论尚未验证、何时需要重新讨论”；仅增加页面或让所有状态变绿不算完成。
